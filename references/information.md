# 信息表达

适用于对象介绍、规格说明、操作指引、活动规则、服务通知和其他以理解为目标的文案。任务完成标准是读者能够正确理解、判断下一步或完成操作。

## 选择信息

先确定读者在这个位置最需要回答的问题。根据任务选择必要内容：对象是什么；能做什么；适合什么情况；何时何地；如何使用；有什么条件；下一步在哪里。

完整介绍只在任务需要时成立。按钮可以只写“下载报名表”，前提是下载行为真实存在、读者知道是哪张表；错误提示应解释问题与可行下一步，不需要介绍全部产品价值。

信息取舍看后果：删去后是否会误解、误操作、错过时间或无法参与？会造成这些后果的信息优先保留。既有上下文已经清楚表达的内容可以不重复。

## 组织方法

- 介绍对象：名称或类别 → 关键功能或用途 → 必要边界。名称陌生时先解释类别。
- 操作指引：前提 → 动作 → 可观察结果 → 异常处理。仅采用实际存在的步骤。
- 活动或通知：发生什么 → 与谁有关 → 何时何地或参与条件 → 怎样处理或参与。
- 规格参数：用统一单位与口径列出关键项；必要时解释其决策含义，不从参数推导没有证据的效果。

以上是可选组织方式，按材料决定，不强制每种文案都有四段。

## 写法

优先用准确的名词和明确的动词。把“实现内容价值的有效承载”改成具体动作，例如“把选中的段落导出为文档”；实际功能未确认时不能使用这类示例。

每句尽量承担一个主要事实，条件紧贴所限制的表述。保持同一对象的称呼一致；介绍操作时用界面中的实际名称。数字、单位、范围、时区和日期不能在改写中漂移。

面向第一次接触的读者，解释会妨碍理解的术语；专业用户已熟悉的词无需逐一释义。不要通过删除必要细节来追求通俗，也不要用专业词堆砌权威感。

相对时间只有在使用时间明确时才安全。长期展示的文案优先使用明确日期；“今天截止”不能在常驻页面中无限保留。真实日期需来自材料或核查。

## 常见失败与改法

| 问题 | 为什么妨碍任务 | 如何修改 |
|---|---|---|
| 抽象形容词多，对象不明 | 读者不知道实际提供什么 | 补类别、动作或结果，删无用形容词 |
| 参数完整但读者看不懂 | 信息无法支持理解和判断 | 保留参数，并解释与本任务有关的含义 |
| 步骤漏前提或入口 | 读者无法执行 | 补真实入口、条件和顺序 |
| 先铺长篇情绪再给关键事项 | 找信息成本过高 | 提前放必要事项，压缩铺垫 |
| 限制藏在远处 | 主句可能造成误解 | 让条件与主张同时被看到 |
| 短句依赖不存在的上下文 | 单独出现时失去意义 | 补最低限度对象或明确相邻内容 |

## 验收

读者能否用自己的话正确复述关键事项？能否按文案完成真实步骤？有没有两个合理但互相冲突的解释？重要条件是否在该出现的位置？

信息准确且适合场景就是合格结果。无需再添加情绪句、传播口号或购买理由。若任务同时需要选择或向往，再读取相关模式，将这些内容放在合适位置。
