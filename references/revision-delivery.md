# 改稿与交付

用于已有内容、多版本、诊断、长文、跨渠道适配和特殊格式。保持用户任务范围，交付实际需要的结果。

## 新写

从材料提取事实与目标，选模式，组织内容，再按目标检查。没有风格要求时使用准确、自然、具体的语言；默认交付一个最佳版本。

内容需要标题、副标题、正文、按钮或口播分段时，按实际载体安排。用户只要标题，不附一篇正文；用户要完整页面文案，则检查页面各部分之间是否重复、遗漏或承诺冲突。

## 最小必要改稿

先阅读全文、上下文、批注及已确认内容。识别不可改部分，保留原意、主语、术语、视角、章节功能、信息顺序和已成立的表达。

按问题类型决定修改范围：

| 问题 | 优先动作 |
|---|---|
| 错字、标点、病句 | 局部修正，不重构全文 |
| 事实或承诺不成立 | 核查、限定或删除该处，检查受影响句子 |
| 理由与读者无关 | 调整关键利益或证据，保留相关事实 |
| 场景空泛 | 改具体动作和细节，不自动增加情节 |
| 标题与正文不符 | 调整标题承诺或补正文实际缺口 |
| 结构妨碍任务 | 必要时重排相关段落，并保留已确认内容 |
| 品牌语气不一致 | 调整不相容措辞，保留事实和必要信息 |

用户只要求某种问题清理时，仅处理该范围，其他可改问题不自动扩成全面重写。用户已确认但事实有疑点的内容，明确指出具体问题，避免静默保留或扩大改稿。

改后对照原稿，检查新增了什么事实、删去了什么条件、改变了什么立场。解释修改原因只在用户要求或关键冲突需要时提供。

## 文案诊断

先确定目标、读者和场景，再评价。缺少场景时可作有限诊断，例如指出歧义、事实越界或明显重复；不能凭想象的销售目标判定整稿失败。

使用“具体原句或位置 → 问题 → 对任务的影响 → 建议修改”的结构。区分必须修正的问题与可选的表达偏好。保留有效内容的依据，但无需逐句赞评。

用户只要求诊断时，不必附完整重写；需要示范时给局部示例即可。用户要求诊断并改稿时，先交付可用稿，再提供简短、有依据的说明，或按指定顺序组织。

## 指定功能改写

用户指定信息、选择、向往或传播功能时，保持同一对象、同一事实与必要条件，改变表达承担的任务。不能为了向往补造效果，也不能为了传播补造公共事件。

用户要求“五层都写”时，按四种任务模式提供四稿，再给品牌表达方向或品牌约束下的示范稿；简要说明品牌表达可贯穿前四种。若用户有明确的五稿格式，遵守格式并准确标识差异，不再排名。

## 多版本与比较

版本数、标签和长度按用户要求。每版采用实际不同的角度、功能、语气或结构，同时保留相同事实与关键条件。用于比较效果时，不让不同优惠、期限或对象混入实验。

用户未指定版本数，不以“大量备选”代替最佳结果。用户要多个方向时，各方向应完整可用。推荐版本依据目标与约束，不能称某一版天然高级或必定高转化。

需要解释差别时，可以用短表列“主要角度／适用位置／事实依据／取舍”。用户只要文案时不附策略表。

## 跨渠道适配

先保持对象、事实、条件和主目标一致，再按新位置调整信息密度、句长、节奏、入口及上下文。重新安排内容，不只机械缩短。

| 载体 | 适配重点 |
|---|---|
| 海报 | 主副标题分工，独立可读性，画面是否承担必要信息 |
| 详情页或落地页 | 适用人群、价值、依据、条件与行动入口相互承接 |
| 社交帖 | 首段入口、可分享单元、正文兑现、对象关联 |
| 公众号或长文 | 主语和视角统一，段落有实际作用，避免重复铺陈 |
| 口播 | 按口头理解安排停顿，数字易听清，展示与话语相符 |
| 邮件或通知 | 事项、时间、责任、下一步清楚，主题与正文一致 |
| 按钮或流程提示 | 动作与实际结果一致，长度适合位置，异常时有可行下一步 |

口播时长应根据实际试读或明确的语速估算，估算应标明；没有实际计时不能宣称精确秒数。不要假设各平台通用同一字数与规则。

## 长度与格式

严格字数要求时按用户计数口径检查。用户未定义口径、但要求精确上限时，可按“所有可见字符含标点，不计空格与换行”核算，并让成品留有余量；不用虚假的平台通用口径。标题与正文分别限制时分别计数。

中文默认使用全角标点；字母、数字前后不加无意义空格。遵循用户指定的语言、地区习惯或双语格式，保留链接、型号、代码等需要的原始字符。

文字应具体、自然、信息密度适当。减少空泛评价、抽象名词串、机械排比和重复收束。默认避开“不是……而是……”式对举，直接写清实际关系；用户要求保留的原句不因个人风格偏好而改动。

引语、数字、编号、链接、行动入口和关键名称逐项核对。输出中的事实不能因润色漂移。

## 交付物

纯文本、Markdown及结构化字段可直接交付。能用所在环境支持的写作容器时按其约定呈现，不把解释包成可复用正文。

用户要求文件时，按可用工具和文档规范生成并检查实际文件；原稿与来源材料保持只读。Word、PPT、网页的排版与功能验收属于相应载体的要求，不能仅凭文案完成就宣称整体交付完成。

默认只显示用户需要的成品。必要的事实待核、来源或实质冲突说明置于成品之外，精简到具体问题。没有未解决事实问题就不附泛化免责声明。

用户要求发送、发布或投放时，依据现有明确授权与环境权限执行；没有授权的文案任务止于完成稿件或保存文件。不得把写作过程写进对外正文。
